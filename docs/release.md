# SiftForge Release Process

This document describes the release process for SiftForge.

SiftForge currently publishes:

- crates.io package
- GitHub Release
- prebuilt archives for macOS, Linux, and Windows
- shell and PowerShell installers generated by `dist`

## Requirements

- Rust stable
- Cargo
- crates.io account with publish access
- GitHub repository access
- `dist` installed

Install `dist`:

```bash
cargo install cargo-dist --locked
```

Verify:

```bash
dist --version
```

## Pre-Release Checklist

Before cutting a release:

1. Confirm the working tree is clean or contains only intended release changes.
2. Confirm CI is passing on `main`.
3. Review `README.md`, `CHANGELOG.md`, and docs for accuracy.
4. Run the full local gate.

```bash
cargo fmt --all -- --check
cargo check --all-targets
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

## Prepare Version

Update the version in `Cargo.toml`.

Example:

```toml
version = "0.1.2"
```

If dependencies changed, make sure `Cargo.lock` is updated.

## Update Changelog

Move relevant entries from:

```md
## [Unreleased]
```

to a dated release section:

```md
## [0.1.2] - YYYY-MM-DD
```

Then reset `Unreleased`:

```md
## [Unreleased]

### Added

- Nothing yet.

### Changed

- Nothing yet.

### Fixed

- Nothing yet.
```

## Verify Packaging

Check package contents:

```bash
cargo package --list
```

Run a crates.io dry run:

```bash
cargo publish --dry-run
```

Run a dist plan:

```bash
dist plan
```

The plan should list the intended version and expected artifacts.

Expected artifact types include:

- source archive
- checksums
- shell installer
- PowerShell installer
- macOS archives
- Linux archives
- Windows zip

## Commit Release Prep

Commit version and changelog updates:

```bash
git add Cargo.toml Cargo.lock CHANGELOG.md
git commit -m "Prepare vX.Y.Z release"
git push
```

Replace `X.Y.Z` with the release version.

## Publish To Crates.io

Publish:

```bash
cargo publish
```

After publishing, verify install:

```bash
cargo install siftforge --force
siftforge --version
```

The version should match the release.

## Create Git Tag

Tag the release:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

The `dist` GitHub Actions workflow should run after the tag is pushed.

## Verify GitHub Release

After the release workflow completes, confirm the GitHub Release exists and includes assets such as:

```text
siftforge-aarch64-apple-darwin.tar.xz
siftforge-aarch64-unknown-linux-gnu.tar.xz
siftforge-x86_64-apple-darwin.tar.xz
siftforge-x86_64-pc-windows-msvc.zip
siftforge-x86_64-unknown-linux-gnu.tar.xz
siftforge-installer.sh
siftforge-installer.ps1
sha256.sum
```

## Verify Installer

Test the latest shell installer:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/DovudxonN/siftforge/releases/latest/download/siftforge-installer.sh | sh
siftforge --version
```

Expected:

```text
siftforge X.Y.Z
```

## Post-Release

After release:

1. Check crates.io page.
2. Check GitHub Release page.
3. Check README install instructions.
4. Confirm CI/release workflows are green.
5. Start future work under `CHANGELOG.md` `Unreleased`.

## Notes

- Do not move or rewrite published tags.
- If a release needs a fix after publishing, cut a new patch release.
- Keep crates.io publishing and GitHub tag versions aligned.
- Prebuilt binaries are produced by `dist`; crates.io publishing is still handled by `cargo publish`.
